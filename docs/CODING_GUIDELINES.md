# 함께 코딩할 때의 기본 지침

사용자와 dot이 합의한 기본 지침을 사용자의 2026-10-08 승인에 따라 이 프로젝트에도 적용한다. 상위 시스템·개발자 지침을 준수하며, 저장소 지침과 충돌하면 최신 사용자 요청과 이 프로젝트의 더 엄격한 조건을 우선한다. 기존 계획·구현·유효한 승인을 보존한다.

참고 원문: [mbc-perfect-day-playlist의 CODING_GUIDELINES.md](https://github.com/Hyun828/mbc-perfect-day-playlist/blob/main/docs/CODING_GUIDELINES.md). 공통 작업 원칙만 적용하며 라디오 전용 설정이나 해당 프로젝트의 운영 환경은 가져오지 않는다.

## 1. 개발 환경과 운영 장소

- 개발은 Codex 클라우드를 기본으로 한다. 현재 checkout과 지침을 먼저 확인하고 HOME 환경이나 개인 PC의 로컬 개발로 임의 전환하지 않는다. HOME 관련 환경 변수도 다른 용도로 재설정하지 않는다.
- 개발 장소와 실제 서비스 운영 장소는 별개다. 기존 오픈클로용 미니 PC를 운영 장소로 검토할 수 있으며, 이것이 로컬 개발·설치·배포를 자동으로 승인하는 것은 아니다.
- 합의 없이 개발·운영 환경이나 구조를 바꾸지 않는다. 실제 제약이 있으면 원인과 최소 대안을 설명하고 아직 필요한 결정만 확인한다.

## 2. 코딩 전 범위와 완료 기준

- 코딩 전에 이번 범위·제외 범위, 개발 및 운영 환경, 필요한 권한·연동, 데이터 보관처, 비용·한도, 실패·재시도 방식과 사용자가 확인할 완료 기준을 정한다.
- 이미 합의한 계획과 구현을 재활용하고 필요한 차이만 조정한다. 매 작업마다 계획을 처음부터 다시 세우거나 전체 구조를 바꾸지 않는다.
- 실제 사용에 필수적인 인증·연동·사용자 접근 경로를 먼저 확인한다. 핵심 가정이 미확인인 상태에서 기능이나 운영 도구를 불필요하게 확장하지 않는다.

## 3. 비용과 사용 한도

- 무료 API·무료 한도와 기존 자원을 우선한다. 호출 빈도·재시도·저장·네트워크 사용량과 실제 제공 한도를 확인하며, 근거 없이 무료 운영이나 비용 0을 보장하지 않는다.
- 일반 원칙은 **Codex 한도 → Gemini Pro 한도 → 그 외 유료 사용은 사용자 승인** 순이다. 구독 한도와 API 크레딧·서버 요금은 별개이며 서로 대체할 수 있다고 가정하지 않는다.
- **이 프로젝트는 Codex만 사용하고 추가 유료 서비스를 도입하지 않는 조건을 우선한다.** Gemini나 다른 서비스로 임의 전환하지 않는다. 한도가 부족하면 이를 알리고 범위·빈도·방식을 조정한다.
- 이 원칙은 새 결제·구독·계정 연결·API 키 생성·권한 확대·외부 자료 전송을 자동 승인하지 않는다. 비밀정보를 채팅·소스·로그에 기록하지 않는다.

## 4. 변경 범위에 맞는 검증

- 보안·개인정보·데이터 손실과 다음 단계의 성립에 필수적인 확인은 즉시 수행한다. 그 외 검증은 관련 변경을 묶어 수행하고, 동일 코드·환경에 대한 전체 검증을 반복하지 않는다.
- 전체 테스트·빌드는 필요한 통합 지점이나 최종 코드 반영 전에 변경 영향에 맞춰 수행한다. 모의 검증·실제 인증 및 연동·실제 운영 완료와 통과·실패·미실행을 구분한다.
- 문서만 변경하는 작업에서는 앱 테스트·빌드를 실행하지 않는다. 문서 내용·링크·차이와 커밋에 포함될 파일을 확인한다.

## 5. 승인·게시·인계

- 이미 승인된 목표와 권한은 재사용한다. 일상적이고 되돌릴 수 있는 구현 선택마다 승인을 반복하지 않는다. 새 비용·권한·운영 배포 등 합의 범위를 벗어나는 행동만 구체적으로 준비한 뒤 필요한 결정을 확인한다.
- 기존 사용자 파일과 미게시 구현을 보존한다. 문서만 게시하도록 승인된 경우 문서만 별도 커밋하고, 앱·CI·배포 설정을 함께 게시하지 않는다. 미게시 앱 변경의 동반 게시나 앱 배포를 유발할 위험이 있으면 해당 장애를 보고한다.
- 실제 읽은 지침, 변경 파일, 검증 범위, 게시 여부와 커밋을 간단히 보고한다. 원격 게시를 요청받으면 원격 커밋과 파일 범위를 확인한다.
- 사용자가 결과를 열 수 있는지 확인하기 전에는 인계 완료라고 하지 않는다. 사용자가 열 수 있는 경로를 제공하고, 원격 게시 확인과 사용자 화면에서의 접근 확인을 구분한다. 사용자 접근이 미확인이면 그 상태를 명시한다.
