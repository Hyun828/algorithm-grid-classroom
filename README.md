# 초등 5학년 알고리즘 격자 미션 웹앱 구현 계획서

문서 상태: Codex 구현 착수용 1차 계획

작성일: 2026년 10월 8일

이 계획서는 초등학교 5학년 실과 수업에서 사용할 학생용 알고리즘 활동 웹앱과 교사용 실시간 대시보드의 구현 범위를 정의한다. 수업은 40분씩 2차시로 운영하며, 학생이 실행 전에 충분히 생각하고 알고리즘을 작성한 뒤 실행 결과를 근거로 수정하는 과정을 중심에 둔다. 첫 구현 목표는 실제 학급에서 안정적으로 사용할 수 있는 최소 기능 제품이다.

## 1. 프로젝트 목표

- 학생이 알고리즘을 문제 해결을 위한 정확하고 순서 있는 명령으로 이해한다.
- 학생이 자연어, 순서도, 의사 코드로 같은 알고리즘을 표현한다.
- 학생이 자전거 문제와 독자적인 격자 미션을 해결한다.
- 학생이 반복되는 명령을 찾아 고정 횟수 반복문으로 바꾼다.
- 교사가 학생별 작성, 실행, 오류, 수정, 완료 상태를 실시간으로 확인한다.
- 회원가입과 실명 수집 없이 수업 코드와 학생 번호 또는 별칭으로 참여한다.

이번 수업에서는 조건문, 변수, 함수, 중첩 반복을 다루지 않는다.

## 2. 구현 원칙

1. 수업 목표를 게임의 점수나 속도보다 우선한다.
2. 학생은 `관찰 → 경로 계획 → 전체 알고리즘 작성 → 실행 → 오류 확인 → 수정` 순서로 활동한다.
3. 교사가 생각 시간을 보장할 수 있도록 실행 기능을 잠그거나 열 수 있게 한다.
4. 최초 초안, 수정안, 최종안을 구분해 저장한다.
5. 교사는 학생 답안을 대신 수정하지 않고 정형화된 힌트만 보낸다.
6. 학생 순위, 공개 점수판, 학생 간 채팅을 만들지 않는다.
7. 교과서 지면과 Minecraft의 명칭, 캐릭터, 그래픽, 음원을 복제하지 않는다.
8. 학교망 장애가 발생해도 이미 열린 학생 화면에서는 작성과 실행을 계속할 수 있게 한다.

## 3. 사용자와 사용 환경

### 3.1 학생

- 초등학교 5학년
- 1인 1PC를 기본으로 하되 2인 1PC도 운영 가능
- 최신 Chrome 또는 Edge 사용
- 회원가입 없이 6자리 수업 코드와 번호 또는 별칭으로 접속

### 3.2 교사

- 수업 생성, 활동 개방, 실행 허용, 반복 블록 개방을 제어
- 학생의 현재 상태와 도움이 필요한 지점을 확인
- 전체 또는 개별 학생에게 정형 힌트 전송
- 수업 종료와 데이터 삭제 실행

### 3.3 기본 규모

- 학급당 학생 30명
- 부하 시험은 교사 화면과 여유분을 포함해 40개 클라이언트로 실시
- 기본 화면 해상도는 1366×768 이상

## 4. 40분씩 2차시 수업 흐름

### 4.1 1차시 정확한 알고리즘 만들기

| 시간 | 학생 활동 | 웹 기능 |
|---|---|---|
| 0~3분 | ‘빵에 잼 바르기’를 5개 안팎의 명령으로 작성 | 자유 입력, 초안 저장 |
| 3~9분 | 샌드위치 알고리즘 영상 시청과 결과 예측 | 예측 문항, 교사용 영상 링크 |
| 9~14분 | 빠지거나 모호한 명령 찾기 | 초안과 수정안 비교 |
| 14~18분 | 알고리즘의 뜻과 정확한 명령의 조건 정리 | 개념 카드 |
| 18~29분 | 자전거 문제를 분석하고 전체 알고리즘 작성 | 경로 메모, 명령 편집, 실행 잠금 |
| 29~35분 | 작성한 알고리즘 단계별 실행 | 한 단계 실행, 현재 명령 강조 |
| 35~40분 | 오류 수정 및 자연어 최종안 제출 | 수정 이력, 최종 제출 |

도입 영상은 교사 기기에서만 재생한다. 기본 링크는 [Exact Instructions Challenge PB&J Classroom Friendly](https://www.youtube.com/watch?v=FN2RM-CHkuI)로 하되, 학교망에서 차단되면 교사가 명령 카드를 문자 그대로 실행하는 대체 활동을 사용한다.

### 4.2 2차시 격자 미션과 반복문

| 시간 | 학생 활동 | 웹 기능 |
|---|---|---|
| 0~4분 | 자연어, 순서도, 의사 코드 비교 | 세 표현 방식 예시 |
| 4~10분 | 자전거 알고리즘을 순서도와 의사 코드로 변환 | 순서도 블록, 의사 코드 입력 |
| 10~12분 | 탐험 로봇의 명령과 격자 규칙 확인 | 연습 조작 |
| 12~23분 | 미션 1 에너지 수정 운반 | 계획, 작성, 실행, 수정 |
| 23~28분 | 반복되는 명령 찾기와 반복문의 의미 이해 | 반복 전후 비교 |
| 28~38분 | 미션 2 다리 만들기 | 순차 알고리즘을 반복문으로 변환 |
| 38~40분 | 출구 평가 | 2~3문항 제출 |

두 차시에서 알고리즘을 계획하고 작성하며 검증하고 수정하는 시간을 합계 45분 이상 확보한다.

## 5. 학생용 화면

### 5.1 접속 화면

- 학생용 공통 URL
- 6자리 수업 코드
- 학생 번호 또는 별칭
- 동일 수업 내 번호 중복 확인
- 같은 기기에서 재접속하면 기존 풀이 자동 복구
- 다른 기기에서는 교사가 발급한 일회용 복구 코드 사용

### 5.2 공통 수업 화면

- 현재 차시와 활동 단계
- 활동 안내와 남은 생각 시간
- 자동 저장과 서버 동기화 상태
- 온라인, 오프라인, 동기화 중 표시
- 교사가 보낸 힌트
- 도움 요청 버튼
- 잠긴 다음 활동 안내

### 5.3 알고리즘 편집기

- 명령 카드 추가, 삭제, 복제
- 드래그로 순서 변경
- 키보드용 위로 이동, 아래로 이동 버튼
- 대상, 방향, 칸 수, 반복 횟수 선택
- 전체 초기화, 실행 취소, 다시 실행
- 생각 완료
- 한 단계 실행, 전체 실행, 정지
- 초안과 수정안 비교
- 최종 제출

생각 시간에는 실행 버튼을 잠근다. 기본값은 3분이며 교사가 즉시 해제할 수 있다.

### 5.4 실행 결과

- 현재 실행 중인 명령을 강조한다.
- 격자 또는 자전거 상태를 단계별로 갱신한다.
- 실행 불가능한 명령에서 중단한다.
- 정답을 직접 알려주지 않는 오류 문구를 표시한다.
- 반복 실행 중에는 `1/3회`, `2/3회`, `3/3회`처럼 횟수를 표시한다.

오류 문구 예시는 다음과 같다.

- 앞이 막혀 있습니다.
- 이동할 수 없는 칸입니다.
- 먼저 필요한 물건을 가져와야 합니다.
- 반복 횟수와 실제 칸 수를 비교하세요.

## 6. 학습 콘텐츠

### 6.1 정확한 명령의 기준

- 대상: 무엇을 움직이는가
- 행동: 무엇을 하는가
- 순서: 언제 하는가
- 방향과 수량: 어느 쪽으로 얼마나 하는가
- 시작과 종료 상태: 언제 시작하고 끝나는가

정확한 알고리즘은 무조건 긴 설명이 아니라, 필요한 정보가 빠지지 않아 누구나 같은 결과를 만들 수 있는 설명으로 정의한다.

### 6.2 자전거 문제

학습 목적은 대상, 방향, 거리, 실행 순서를 명확히 표현하는 것이다.

규칙은 다음과 같다.

- 자전거는 놓인 방향을 따라 앞 또는 뒤로만 이동한다.
- 한 번에 1칸 이상 이동할 수 있다.
- 다른 자전거를 통과하거나 겹칠 수 없다.
- 앞과 뒤는 화면 방향이 아니라 자전거가 향한 방향을 기준으로 한다.
- 목표 자전거가 출구에 도달하면 성공한다.
- 자전거는 색뿐 아니라 `빨간 1인용`, `초록 2인용`처럼 종류와 번호를 함께 표시한다.

명령 형식은 다음과 같다.

```text
[대상 자전거]를 [앞/뒤]로 [칸 수]칸 이동
```

교과서 스캔 이미지 대신 자체 제작한 6×6 격자와 단순 자전거 도형을 사용한다. 최종 배치는 구현 전 교사가 확인한다. 미션 정의와 화면 코드를 분리하고, 초기 상태에서 목표 상태에 도달 가능한지 자동 테스트한다.

### 6.3 독자 격자 미션 공통 규칙

테마는 `탐험 로봇의 기지 복구`로 한다.

허용 명령은 다음과 같다.

- 앞으로 1칸
- 왼쪽으로 90도 돌기
- 오른쪽으로 90도 돌기
- 물건 줍기
- 물건 놓기
- 앞 칸에 블록 놓기
- `N번 반복하기`

초기 버전에서는 뒤로 이동, 조건문, 중첩 반복을 제공하지 않는다.

### 6.4 미션 1 에너지 수정 운반

5×5 격자의 기본 배치는 다음과 같다. `S`는 시작, `C`는 에너지 수정, `G`는 발전기, `#`은 바위다.

```text
. . . . .
. . # . G
C . # . .
. . # . .
S↑ . . . .
```

목표는 수정을 주워 발전기까지 운반한 뒤 놓는 것이다. 학생은 전체 경로와 알고리즘을 먼저 작성한 뒤 실행한다.

실패 조건은 다음과 같다.

- 격자 밖으로 이동
- 바위 칸으로 이동
- 수정이 없는 곳에서 줍기
- 수정을 갖지 않은 상태에서 놓기
- 발전기가 아닌 곳에 수정 놓기

### 6.5 미션 2 물 위에 다리 만들기

기본 배치는 다음과 같다.

```text
S→  물  물  물  G
```

로봇은 블록 3개를 가지고 시작한다. 물 칸에는 앞 칸에 블록을 놓은 뒤에만 이동할 수 있다.

순차 알고리즘 예시는 다음과 같다.

```text
앞 칸에 블록 놓기
앞으로 1칸
앞 칸에 블록 놓기
앞으로 1칸
앞 칸에 블록 놓기
앞으로 1칸
앞으로 1칸
```

교사가 반복 블록을 열면 다음과 같이 바꿀 수 있다.

```text
3번 반복하기
    앞 칸에 블록 놓기
    앞으로 1칸
앞으로 1칸
```

반복 횟수는 1~10회로 제한하며 반복 블록 안에 반복 블록을 넣을 수 없다. 순차 알고리즘과 반복 알고리즘이 같은 최종 상태를 만드는지 자동 검증한다.

### 6.6 선택 활동

MVP에서는 고정 심화 미션만 제공한다.

- 장애물을 피해 출구 찾기
- 잘못된 반복 횟수 고치기
- 같은 결과를 만드는 두 알고리즘 비교

학생이 직접 격자 문제를 만드는 기능은 수업 시범 운영 후 추가 여부를 결정한다.

## 7. 교사용 실시간 대시보드

### 7.1 수업 생성과 접근

- 교사가 새 수업을 생성한다.
- 시스템이 학생용 URL, 6자리 수업 코드, 교사용 관리 링크를 만든다.
- 학생 수업 코드와 교사 권한을 분리한다.
- 교사용 관리 토큰은 브라우저에 그대로 노출하지 않고 보안 쿠키로 교환한다.
- 같은 수업을 저장해 1차시와 2차시 사이에 재개할 수 있다.

### 7.2 상단 수업 제어

- 접속 인원과 현재 활동
- 생각 시간 시작과 종료
- 실행 버튼 잠금과 해제
- 다음 활동 열기
- 반복 블록 열기
- 전체 또는 개별 정형 힌트 보내기
- 수업 일시 정지와 재개
- 수업 종료
- 수업 데이터 삭제

활동 잠금은 학생 답안을 삭제하거나 화면을 강제로 넘기지 않고 새 실행만 막는다.

### 7.3 전체 상태

다음 상태별 학생 수를 표시하고 선택 시 해당 학생만 필터링한다.

- 접속 대기
- 관찰 중
- 초안 작성 중
- 실행 대기
- 실행 중
- 수정 중
- 완료
- 도움 요청
- 연결 지연 또는 끊김

점수와 완료 속도 순위는 표시하지 않는다.

### 7.4 학생별 카드

- 번호 또는 별칭
- 접속 상태
- 현재 활동과 단계
- 현재 명령 수
- 실행이 멈춘 명령 번호
- 최근 저장 시각
- 수정 횟수
- 도움 요청 여부
- 확인 필요 여부

### 7.5 학생 상세 화면

- 현재 격자 또는 자전거 상태
- 예상 이동 경로
- 최초 알고리즘
- 현재 수정안
- 실행 중인 명령
- 마지막 실패 사유
- 초안과 수정안의 차이
- 반복문 변환 전후 알고리즘
- 활동별 제출 여부

교사는 학생 풀이를 대신 수정할 수 없다.

### 7.6 확인 필요 자동 판정

다음 조건에서 학생 카드를 `확인 필요`로 표시한다.

- 학생이 도움을 요청함
- 같은 명령에서 3회 이상 중단됨
- 5분 이상 초안 변화가 없음
- 수정 없이 실행만 3회 이상 반복함
- 반복 횟수 오류가 연속 발생함
- 30초 이상 연결이 끊김
- 서버 저장이 실패함

| 데이터 | 주요 필드 |
|---|---|
| 수업 세션 | 내부 ID, 참여 코드, 현재 차시·단계, 잠금 상태, 생성·종료·만료 시각 |
| 참여 학생 | 익명 ID, 번호 또는 별칭, 기기 세션 ID, 접속 상태, 마지막 활동 시각 |
| 미션 시도 | 미션 ID, 최초 초안, 현재안, 최종안, 실행 상태, 수정 횟수, 버전 |
| 의미 있는 사건 | 생각 완료, 명령 변경, 실행, 오류, 수정, 제출, 도움 요청 |
| 교사 힌트 | 대상, 정형 문구 ID, 전송·확인 시각 |
| 미션 정의 | 격자, 시작 상태, 장애물, 아이템, 목표, 허용 명령, 실행 제한 |

모든 키 입력과 화면을 기록하지 않는다. 명령 추가, 삭제, 이동, 실행, 오류, 수정, 제출 등 수업 운영에 필요한 사건만 저장한다.

## 9. 권한과 개인정보

- 실명, 이메일, 전화번호, 카메라, 음성, 화면 녹화를 수집하지 않는다.
- 번호와 실제 학생의 대응표는 서비스에 저장하지 않는다.
- 학생은 자기 풀이만 조회하고 변경할 수 있다.
- 학생 코드만으로 교사 기능에 접근할 수 없다.
- 교사 관리 권한은 만료되는 별도 토큰 또는 학교가 허용한 인증으로 보호한다.
- 별칭과 자유 입력은 HTML과 스크립트로 실행되지 않게 처리한다.
- 외부 광고와 행동 분석 도구를 사용하지 않는다.
- 기본 보존 기간은 수업 종료 후 7일이며 교사는 즉시 삭제할 수 있다.
- 실제 보존 기간과 호스팅 위치는 배포 전에 학교 기준을 확인한다.

## 10. 기술 구성 기본안

구현 시작 시 현재 저장소와 배포 대상을 확인한 뒤 확정한다. 별도 지시가 없으면 다음을 기본안으로 사용한다.

- 새 프로젝트 폴더: `algorithm-grid-classroom/`
- 언어: TypeScript
- 웹 프레임워크: Next.js 계열의 현재 작업공간 호환 구성
- UI: React와 CSS 또는 기존 디자인 시스템
- 데이터 접근: 서버 API와 관계형 데이터베이스
- 로컬 복구: IndexedDB
- 검증: 스키마 검증 라이브러리와 순수 TypeScript 미션 엔진
- 단위 테스트: 현재 저장소와 호환되는 테스트 도구
- 브라우저 테스트: Playwright

현재 작업공간의 `robot-telepathy-quiz/`는 별도 작업물로 취급한다. 사용자가 명시적으로 재사용을 요청하지 않는 한 수정하지 않는다. 공통 패턴은 읽기 전용 참고만 허용한다.

실시간 상태 갱신은 다음 우선순위를 사용한다.

1. 배포 환경에서 안정적으로 지원되는 비공개 실시간 채널
2. 서버 전송 이벤트 또는 WebSocket
3. 학교망 호환성을 위한 2~3초 폴링 대체 방식

외부 실시간 서비스나 새 유료 계정이 필요하면 구현 전에 사용자 확인을 받는다. MVP는 95%의 상태 변경이 3초 안에 교사 화면에 보이면 수용한다.

## 11. 오프라인과 재접속

- 구조화된 풀이 데이터는 IndexedDB에 먼저 저장한다.
- 각 변경에 고유 사건 ID와 기기 내 순번을 부여한다.
- 온라인이면 변경을 0.5~1초 단위로 묶어 서버에 전송한다.
- 서버가 확인한 사건만 전송 대기 목록에서 제거한다.
- 재연결 시 미전송 사건을 원래 순서대로 보낸다.
- 서버는 같은 사건 ID를 두 번 받아도 한 번만 반영한다.
- 여러 탭에서 같은 풀이를 열면 한 탭만 편집 가능하게 한다.
- 충돌 시 자동으로 덮어쓰지 않고 로컬 복구본을 보존한다.

MVP는 이미 열린 화면에서 연결이 끊겼을 때 활동을 계속하는 수준을 필수로 한다. 네트워크가 끊긴 상태에서 처음부터 앱을 여는 완전한 오프라인 PWA는 후속 범위로 둔다.

## 12. 구현 순서

각 단계는 앞 단계의 완료 기준을 통과한 뒤 진행한다.

| 단계 | 구현 내용 | 주요 산출물 | 완료 기준 |
|---|---|---|---|
| 0 | 저장소와 실행 환경 점검 | 변경 대상, 실행 명령, 배포 제약 기록 | 기존 파일과 사용자 변경을 훼손하지 않음 |
| 1 | 기술 결정과 새 앱 골격 생성 | 학생, 교사, API 기본 경로 | 빈 화면의 lint, typecheck, build 통과 |
| 2 | 도메인 타입과 미션 정의 형식 작성 | 명령, 격자, 자전거, 실행 결과 타입 | 잘못된 미션 설정이 검증 단계에서 거부됨 |
| 3 | 화면과 분리된 미션 엔진 구현 | 순수 TypeScript 실행기와 단위 테스트 | 경계, 충돌, 방향, 줍기·놓기 판정 통과 |
| 4 | 학생 화면의 정적 프로토타입 구현 | 접속, 수업, 명령 편집, 실행 화면 | 마우스와 키보드로 기본 흐름 완료 |
| 5 | 자전거 문제 연결 | 자전거 격자, 명령 형식, 실행·수정 | 승인된 배치가 목표 상태에 도달 가능 |
| 6 | 에너지 수정 운반 미션 연결 | 5×5 미션과 오류 메시지 | 전체 유효 경로와 주요 실패 조건 테스트 통과 |
| 7 | 반복 블록과 다리 미션 구현 | 단일 반복 블록, 반복 전후 비교 | 순차 풀이와 반복 풀이의 최종 상태가 같음 |
| 8 | 자연어·순서도·의사 코드 활동 구현 | 표현 변환 화면과 제출 | 세 표현 방식이 같은 명령 순서를 보존함 |
| 9 | 데이터베이스와 수업 세션 구현 | 수업, 학생, 시도, 힌트 스키마와 마이그레이션 | 새 데이터베이스에서 마이그레이션 재현 가능 |
| 10 | 학생 접속과 자동 저장 구현 | 수업 코드, 익명 세션, 복구 | 새로고침 후 마지막 확정 상태 복구 |
| 11 | 교사 대시보드 기본 구현 | 상태 집계, 학생 카드, 상세 창 | 학생 변경이 3초 안에 교사 화면에 반영 |
| 12 | 교사 제어와 힌트 구현 | 잠금·해제, 반복 블록 개방, 정형 힌트 | 제어가 답안을 지우지 않고 학생 화면에 반영 |
| 13 | 오프라인 대기열과 재동기화 구현 | IndexedDB, 사건 큐, 중복 제거 | 3분 단절 후 변경이 누락·중복 없이 동기화 |
| 14 | 보안과 개인정보 기능 구현 | 권한 검사, 만료, 삭제 작업 | 학생 간 데이터와 교사 기능 접근이 차단됨 |
| 15 | 접근성 및 반응형 보완 | 키보드 대체 조작, 확대, 텍스트 상태 | 200% 확대와 키보드만으로 핵심 활동 완료 |
| 16 | 통합·부하·브라우저 시험 | 자동 테스트와 시험 결과 | 40클라이언트 90분 시험에서 데이터 유실 없음 |
| 17 | 스테이징 배포와 학교망 리허설 | 운영 안내서, 장애 대응표 | 실제 교사·학생 PC로 사전 수업 흐름 완료 |
| 18 | 운영 배포와 시범 수업 | 운영 URL과 데이터 삭제 절차 | 출시 수용 기준을 모두 충족함 |

## 13. 단계별 Codex 작업 규칙

Codex는 각 구현 단계에서 다음 순서를 따른다.

1. 이 계획서와 저장소 지침을 읽는다.
2. 현재 Git 상태와 기존 사용자 변경을 확인한다.
3. 해당 단계 범위만 구현한다.
4. 단위 테스트와 필요한 통합 테스트를 함께 추가한다.
5. lint, typecheck, test, build를 실행한다.
6. 실제 브라우저에서 학생과 교사 화면을 확인한다.
7. 변경 파일, 검증 결과, 남은 문제를 기록한다.
8. 완료 기준을 통과한 뒤 다음 단계로 이동한다.

미션 엔진, 반복 블록, 권한 검사, 오프라인 동기화는 한 번에 묶지 않고 별도 단계로 구현하고 검증한다.

## 14. 테스트 계획

### 14.1 단위 테스트

- 격자 밖 이동 차단
- 장애물과 자전거 충돌 차단
- 회전과 전진 결과
- 물건 줍기와 놓기 순서
- 다리 블록 설치 조건
- 자전거의 앞뒤 기준
- 반복문 횟수와 실행 순서
- 0회, 음수, 10회 초과 반복 차단
- 전체 실행 100단계 제한과 정지
- 같은 입력이 항상 같은 실행 기록을 생성하는지 확인
- 사건 재전송과 중복 제거

### 14.2 핵심 통합 시나리오

| 시나리오 | 기대 결과 |
|---|---|
| 학생 30명이 1분 안에 입장 | 누락과 중복 없이 교사 명단에 한 번씩 표시 |
| 교사가 다음 활동을 개방 | 정상 연결 학생의 95%가 3초 안에 상태 반영 |
| 10명이 동시에 수정·실행 | 화면 멈춤 없이 학생과 교사 상태가 일치 |
| 학생 연결을 3분 끊고 20개 명령 수정 | 활동 지속 후 원래 순서대로 무중복 동기화 |
| 새로고침과 브라우저 재시작 | 마지막 확정 상태 복구 |
| 1차시 후 같은 기기로 재접속 | 기존 풀이와 단계 복구 |
| 다른 기기에서 복구 코드 사용 | 지정된 학생 세션만 1회 복구 |
| 반복 블록 3회 실행 | 반복 표시와 실제 격자 상태 일치 |
| 학생이 다른 학생 또는 교사 API 접근 | 접근 거부와 데이터 비노출 |
| 별칭에 스크립트 문자열 입력 | 문자로 표시되고 코드가 실행되지 않음 |
| 200% 확대와 키보드 전용 사용 | 핵심 활동 전체 완료 가능 |

### 14.3 실제 사용성 시험

- 교사 1명과 학생 역할 4~6명으로 소규모 시험
- 실제 학교 PC와 관리형 Chrome 또는 Edge에서 시험
- 1차시와 2차시 전체 흐름 리허설
- 학생이 명령 순서 변경, 실행 잠금, 저장 상태, 반복 횟수를 이해하는지 관찰
- 교사가 도움이 필요한 학생을 10초 이내에 찾을 수 있는지 확인

## 15. 접근성 기준

- 모든 핵심 기능을 키보드만으로 사용할 수 있어야 한다.
- 드래그 기능에는 위로 이동, 아래로 이동, 삭제 버튼을 함께 제공한다.
- 색상만으로 자전거, 지형, 상태를 구분하지 않는다.
- 버튼 클릭 영역은 44×44 CSS 픽셀 이상을 목표로 한다.
- 200% 확대에서도 핵심 기능이 잘리면 안 된다.
- 현재 위치와 방향을 글로도 제공한다.
- 실행 중인 명령과 오류 결과를 보조 기술이 읽을 수 있게 한다.
- 애니메이션 정지와 속도 조절을 제공하고 동작 줄이기 설정을 따른다.
- 영상은 자동 재생하지 않는다.

## 19. 출시 수용 기준

다음 조건을 모두 충족해야 실제 수업에 사용한다.

1. 교사가 1분 이내에 수업을 만들고 학생 코드와 관리 링크를 얻는다.
2. 학생이 회원가입 없이 접속해 모든 필수 활동을 완료한다.
3. 초안, 수정안, 최종안이 구분되어 저장된다.
4. 자전거와 격자 미션의 경계, 충돌, 방향, 아이템 상태 판정이 정확하다.
5. 순차 알고리즘과 반복 알고리즘이 같은 최종 상태를 만든다.
6. 학생 상태의 95%가 3초 안에 교사 화면에 반영된다.
7. 새로고침과 일시적 연결 단절 후 풀이가 복구된다.
8. 재연결 시 명령 누락, 순서 변경, 중복 저장이 발생하지 않는다.
9. 학생이 다른 학생의 풀이와 교사 기능에 접근할 수 없다.
10. 40클라이언트 90분 시험에서 제출 데이터가 유실되지 않는다.
11. 키보드만으로 모든 필수 활동을 완료할 수 있다.
12. 교사가 데이터를 즉시 삭제할 수 있고 자동 만료가 동작한다.
13. 실제 학교 PC와 학교망에서 사전 리허설을 완료한다.
14. 교과서와 Minecraft의 원본 그래픽이 배포 파일에 포함되지 않는다.

다른 학생 데이터 노출, 답안 유실, 조용한 덮어쓰기, 반복 실행에 따른 브라우저 멈춤이 확인되면 출시를 중단한다.
