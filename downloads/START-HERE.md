# PC 교실 실행·운영 안내

**이 ZIP은 기능 확인용 프로토타입입니다.** 단위 1,244개·브라우저 158개 검사는 통과했습니다. 90분 API 성능 조건 미통과: 계획 밖 요청 실패 225건, 원인 미확정. 90분 종료 후 자료 무결성은 확인했습니다. 실제 Windows·학교망 운영은 미검증입니다. 상세 결과는 `verification.json`, 미니 PC 자동 검사는 `RUN-LOAD-TEST.cmd`를 확인하세요.

개발은 Codex 클라우드에서 진행하고, 집 Windows 11 미니 PC(Ryzen 5 PRO 6650H, 16GB RAM)는 수업 서버로 사용한다. 학생과 교사는 PC의 Chrome 또는 Edge로 접속한다. 추가 유료 API·호스팅·DB를 사용하지 않으며 기존 OpenClaw와 별도로 실행한다.

## 시작하기

1. 새 ZIP을 새 폴더에 **전부 압축 해제**한다. 예: `C:\ClassroomPilot-PC`. ZIP 안에서 직접 실행하지 않는다.
2. `START.cmd`를 실행한다. 관리자 실행은 필요 없다. 처음에는 무료 실행 패키지를 내려받으며 서버 준비 후 **교사용 화면 열기 / 학생용 화면 열기** 안내 파일이 열린다.
3. 다른 PC에서도 접속하려면 `TUNNEL.cmd`를 실행한다. HTTPS 주소를 받으면 같은 안내 파일이 갱신되어 열린다. 교사는 **교사용 화면 열기**로 교실을 준비하고, 학생에게는 **학생용 링크만** 전달한다.
4. 학생은 링크에서 번호나 별칭만 입력한다. 수업 코드는 입력하지 않는다. 같은 브라우저로 다시 들어올 때는 처음 쓴 번호·별칭을 사용한다.
5. 수업 중 START와 TUNNEL 창을 유지한다. 수업이 끝나면 각각 Ctrl+C로 종료한다. 다른 Node·OpenClaw 프로세스를 일괄 종료하지 않는다.

안내 파일이 자동으로 열리지 않으면 START 창에 표시된 `.links.html` 경로를 파일 탐색기에 붙여 넣어 연다. 기본 위치는 `%LOCALAPPDATA%\AlgorithmGridClassroom\pilot-data.sqlite.links.html`이다. TUNNEL 실행 전에는 이 PC에서만 열리는 주소이며, TUNNEL 실행 뒤 안내 파일에 표시된 학생용 HTTPS 주소를 공유한다.

**안내 파일 전체와 교사용 링크는 학생에게 보내지 않는다.** 교사용 링크에는 관리 권한이 들어 있다. 이를 열면 주소의 관리 키를 지우고 비공개 쿠키로 교환한다. 교사가 다른 브라우저나 새 터널 주소에서 다시 접속할 때는 개인 안내 파일의 교사용 버튼을 다시 사용한다.

## 수업 진행과 다음 학급

- 학생 현황에서 수업 진행·활동 관리를 연다. 실행 허용, 생각 시간, 일시 정지와 활동 열기·닫기를 구분한다.
- **이 활동으로 모두 이동**은 답안을 보존한 채 선택한 미션 첫 화면으로 모은다. 학생은 이후 단계 바로 가기로 열린 단계를 자유롭게 오간다.
- 같은 학급을 이어 가려면 초기화하지 않는다. 같은 주소·브라우저로 들어오면 저장된 풀이를 이어 쓴다.
- 다음 학급이 들어올 때 **다음 학급으로 초기화**를 누르고 새 학급 이름·차시를 확인한다. 현재 학생·계획·명령·제출·힌트를 삭제하고 빈 학급을 시작한다. 교사와 학생 링크 경로는 그대로다. 취소를 선택하면 아무것도 지우지 않는다.
- **현재 수업 데이터 완전 삭제**는 현재 학급을 비운 채 종료한다. 다음에 교사용 링크를 다시 열 때 새 수업을 준비한다. 수업 종료만 하면 읽기 전용으로 남으며 즉시 삭제와 다르다.
- 기존 학생의 쿠키나 늦게 도착한 저장 요청은 새 학급에 사용할 수 없다. 온라인 학생 화면도 초기화 안내로 바뀐다. 닫혀 있거나 오프라인인 브라우저의 보관본은 다음 접속 때 정리한다.

정규 학생 25명, 검증 목표 30명에 여유를 두어 현재 학급의 신규 참여 상한은 40명이다. 기존 학생의 재접속은 상한에서도 허용한다. 다른 브라우저에서 번호만 똑같이 입력해 기존 학생 답안을 가져올 수는 없다.

## 기존 시험판에서 바꾸기

1. 새 ZIP은 **별도 폴더**에 푼다. 예전 폴더와 DB는 보관한다.
2. 기존 START 창을 Ctrl+C로 종료한 뒤 같은 Windows 사용자로 새 `START.cmd`를 실행한다. 같은 DB·포트 설정을 사용한다. 필요한 구조 갱신 전 DB 백업을 만든다.
3. 이번에 처음 역할 링크 안내를 사용하는 경우에는 기존 TUNNEL도 종료한 뒤 **새 폴더의 TUNNEL.cmd**를 실행하여 새 안내 파일을 만든다. 이 경우 HTTPS 주소가 바뀌므로 새 파일의 버튼과 학생 주소를 사용한다.
4. 이 버전 이후의 일반 업데이트에서는 TUNNEL과 예전 폴더를 유지하고 START만 교체할 수 있다. 실행 상태 정보로 현재 주소를 이어받았는지 개인 안내 파일에서 확인한다.

최초 역할 링크 설치 시 유효한 열린 수업이 정확히 하나면 그 학생·답안·수업 제어를 이어받는다. 열린 수업이 여러 개면 임의로 선택하거나 지우지 않고 새 교실을 준비한다. 데이터가 필요하면 초기화 전에 기존 관리 화면에서 확인한다.

**Quick Tunnel은 다시 실행하면 인터넷 주소가 바뀐다.** 학급 초기화만 할 때는 주소가 유지된다. 터널 주소가 바뀌면 기존 학생의 쿠키와 브라우저 저장소가 새 주소로 자동 이전되지 않는다. 수업과 두 차시를 이어 가는 동안 터널을 유지하고, 다음 학급을 시작할 때만 초기화한다. 고정 도메인·학교망 가용성이 검증된 정식 배포로 간주하지 않는다.

## 데이터와 복구

기본 DB는 `%LOCALAPPDATA%\AlgorithmGridClassroom\pilot-data.sqlite`이다. 앱 폴더 밖에 있으므로 업데이트로 삭제되지 않는다. DB 옆 `.room-key`는 설치 관리 키, `.links.html`은 개인 접속 안내, `.runtime.json`은 실행 상태다. 이 파일들을 공개 폴더·학생 공유 폴더·ZIP에 넣지 않는다. 키를 잃거나 DB와 키가 다르면 실행을 중단하며 임의로 새 키를 덮어쓰지 않는다.

기본 세션은 생성 후 7일 유효하며 수업 종료 시 종료 후 7일까지 서버 보관한다. 만료 데이터는 서버 요청 때 최대 60초 간격과 START 때 실제 정리한다. 학생 브라우저는 서버가 알려 준 기간과 초기화를 확인해 해당 학급 자료를 정리한다. 이전 링크 방식의 로컬 복구본은 종료에 따른 연장을 놓치지 않도록 기존 만료 시각에서 최대 7일을 더 보관할 수 있다. 닫힌 PC·오프라인 브라우저에서 시각에 맞춰 정리가 실행됐다고 간주하지 않는다.

DB 갱신 전 백업은 DB 옆 `before-v…-to-v…` 이름으로 만든다. WAL에 있던 최신 저장까지 포함해 검증하며, 실패하면 갱신을 중단한다. 알려진 완료 백업은 생성 후 7일이 지난 다음 START 때 정리한다. 초기화·삭제 뒤에도 이전 답안이 백업에 남아 있을 수 있다. 관리 키는 설치를 쓰는 동안 보관하고 답안 백업과 수명 주기를 구분한다.

복구할 때는 START와 TUNNEL을 종료하고 문제 DB·WAL·SHM·키를 함께 별도 개인 폴더에 보존한다. 검증된 완료 백업을 **새 DB 경로**로 복사하고 원래 `.room-key`도 그 파일 이름 뒤에 복사한다. `START.cmd --database "D:\ClassroomData\restored.sqlite"`로 먼저 확인한 다음 같은 `--database`를 지정해 TUNNEL을 실행한다. 실행 중인 DB 위에 덮어쓰거나 `.partial` 파일로 복원하지 않는다. 복원은 백업 이후의 수정·초기화·삭제도 되돌릴 수 있으므로 학생 참여 전에 확인한다.

## 포트와 장애 대응

기본 포트는 3210이다. 다른 프로그램이 쓰는 포트를 강제로 빼앗지 않는다. `START.cmd --port 3212`로 빈 포트를 선택하면 TUNNEL은 실행 상태 파일의 포트를 사용한다. DB 경로를 직접 지정했다면 START와 TUNNEL 모두 같은 `--database`를 지정한다. 전역 Node·PATH·방화벽·공유기·OpenClaw·자동 시작은 변경하지 않는다.

| 상황 | 대응 |
|---|---|
| 개인 안내가 안 열림 | 실행 창의 `.links.html` 경로를 파일 탐색기에서 열기 |
| 학생에게 교실 준비 전 표시 | 교사용 링크를 먼저 열어 현재 교실 준비 |
| 별칭이 이미 사용 중 | 원래 브라우저·별칭인지 확인. 다른 학생 답안을 넘겨주지 않음 |
| 일시 연결 단절 | 학생 기기 보관을 유지하고 재연결 후 저장됨 확인 |
| START 오류·백업 실패 | 기존 DB·키·WAL·SHM 보존, 다른 앱 프로세스 종료 금지 |
| 학교에서 주소가 안 열림 | 학교망 접속 미확인으로 기록하고 인쇄 활동·교사 시연으로 전환 |
| 다음 학급 시작 | 교사 화면의 다음 학급으로 초기화, 동일 학생 링크 재사용 |

## 실제 운영 전 확인

클라우드 자동 검사와 실제 PC 검증을 구분한다. 목표는 학생 30명과 교사 1명으로 90분이며 실제 학급은 25명이다. 실제 미니 PC에서 OpenClaw와 함께 실행한 부하·학교망 접속·PC의 200% 확대·학교 수업 리허설은 별도 확인해야 한다. ZIP의 `operating-rehearsal.md`에 순서와 판정표를 둔다. 현재 클라우드에는 미니 PC 원격 실행 연결이 없어 자동 적용하지 않는다.

### 미니 PC에서 자동 부하 검사하기

1. 이 ZIP의 `START.cmd`를 한 번 정상 실행해 필요한 패키지를 준비한다.
2. 실제 수업이 없는 시간에 같은 폴더의 **RUN-LOAD-TEST.cmd**를 실행한다. 기존 OpenClaw는 평소처럼 실행해 둔다. 수업 서버와 다른 시험 전용 포트 3213과 새 시험 DB를 사용하며 현재 학급 자료는 건드리지 않는다. TUNNEL은 필요 없다.
3. 합성 학생 30명과 교사 API가 **실제 90분** 동안 저장·재접속·시험 서버 재시작을 검사한다. 창을 유지한다. 취소하려면 Ctrl+C를 한 번 누르고 종료 기록을 기다린다.
4. 마지막 PASS 또는 FAIL과 `report.json` 경로를 확인한다. 결과는 `%LOCALAPPDATA%\AlgorithmGridClassroom\load-tests` 아래 실행별 폴더에 남는다. 실패 결과도 지우지 않는다. 결과를 전달할 때는 **report.json만** 사용한다. 같은 폴더의 DB·관리 키·private-checkpoint.json은 보내지 않는다.

이는 이 PC의 API·저장 검사다. 실제 학생 30대의 화면이나 집 인터넷·학교망을 검사하지 않으며, Windows에서는 서버 메모리 사용량을 작업 관리자에서 별도로 확인한다. 기능 검사 통과와 90분 성능 검사 결과는 ZIP의 `verification.json`에서 구분한다. 자동 검사 실패를 실제 수업 사용 완료로 표시하지 않는다.
